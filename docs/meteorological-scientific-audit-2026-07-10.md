# Weather App Meteorological and Scientific Audit

**Audit date:** 2026-07-10; follow-up implementation and final blind-spot review completed 2026-07-11
**Branch:** `codex/meteorological-accuracy-audit`
**Repository baseline:** `c77a00d`; independent follow-up review of `4435fc1`
**Purpose:** Scientific correctness, methodological transparency, analyst usefulness, source-data integrity, and interactive performance.

## Executive assessment

The application has an unusually broad and mostly coherent deterministic-model analysis suite. Unit conversions, pressure-level fields, precipitation accounting, thermodynamic calculations, most severe-weather diagnostics, the winter accumulation framework, and the new MapLibre presentation are generally sound. Deliberate compute or presentation tradeoffs are usually reasonable when they are disclosed.

The audit nevertheless confirmed several material errors that should not be treated as tradeoffs:

1. Cloud-ceiling no-ceiling sentinels are interpolated as physical heights, and the same MSL-to-AGL subtraction is applied to models whose UPP ceiling field is already AGL.
2. Point-sounding winds from Lambert-conformal models are sampled as grid-relative components rather than earth-relative components. This rotates hodographs and every wind-derived sounding diagnostic by as much as roughly 20 degrees near domain edges.
3. The Cobb/NBM v4.2 snow-ratio perturbations are shifted 1 C warm.
4. Effective-layer SCP omits the current SPC most-unstable CIN term.
5. GFS snowfall presentation smoothing also changes hover values that are described as raw data.
6. Learned snowfall methods are evaluated outside their documented training geography.
7. Synoptic-center logic can fabricate or over-promote global extrema and changes the center set when contour detail changes.
8. Ambiguous marching-squares cells use an arithmetic-center shortcut rather than a topology-preserving asymptotic decision.
9. Timeline warming downloads multi-gigabyte hover archives for every frame while failing to warm the tiny height-contour vectors that the user is actually waiting for.
10. Several labels, caveats, comparison panels, exports, and legends omit scientifically important datum, interval, provenance, method, or valid-time information.

Every confirmed low/no-significant-compute correction in this register was implemented and regression-tested on this branch. The timeline work substantially reduces network, decode, memory, and main-thread work. GeoJSON consolidation now replaces 23 MapLibre sources with 3 for a representative synoptic-plus-one-height stack, and selected-frame reprioritization no longer aborts still-useful adjacent-vector downloads. The optional science paths and hourly GFS tier are explicit, versioned choices rather than changes to default output. More expensive or judgment-dependent enhancements remain recommendations rather than defects. The final disposition and residual risks appear at the end of this report.

## Scope and definition of verification

The audit inspected all 79 public catalog products (including the five pressure-height contour products), the synoptic isobar/thickness/center overlays, point soundings, sounding comparison and export, hover sampling, legends and caveats, run/frame selection, source acquisition and GRIB selection, regridding and vector rotation, binary hover encoding, raster and vector generation, caching and warming, share state, stale-run indicators, MapLibre rendering, and the relevant automated tests and prior accuracy work.

Verification means the implementation and metadata were traced to their actual input records and calculations, then compared with primary or pinned method sources where a published definition exists. It does not mean that a deterministic model forecast has been observationally validated. A mathematically correct transformation can still inherit model bias, representativeness limits, and forecast error.

Compute classifications used throughout this report:

- **None:** metadata, labeling, validation, or selection changes with no meaningful additional runtime work.
- **Negligible:** constant-time arithmetic or small UI state changes.
- **Small:** bounded extra work on the selected frame or a few adjacent frames.
- **Moderate:** extra profile, temporal, or domain analysis that can be noticeable during artifact production.
- **High:** material expansion of dense-grid, temporal, or profile computation or storage.

## Evidence and reproducibility

The review used source inspection, automated tests, live artifact manifests, decoded binary hover files, local network traces, synthetic numerical cases, and pinned primary implementations. Important measured facts include:

- The examined NAM 3 km run contained 61 frames and 76 artifact parameters.
- Its compressed hover-grid archives totaled approximately 3.9 GiB; decoded across the run they represented approximately 13.77 GB.
- A representative F024 hover file was 71,197,923 bytes compressed and 225,799,035 bytes decoded, with 72 Int16 variables on a 1600 by 980 grid.
- A five-second timeline trace produced 22 unique hover downloads totaling approximately 1.46 GB. The corresponding 22 synoptic vectors totaled only about 281 KB.
- All five pressure-level height-vector sets for the run totaled only approximately 3.304 MB. Synoptic vectors totaled approximately 10.355 MB.
- In a representative detailed frame, the simple center payload contained 4 highs and 7 lows while the detailed payload contained 12 highs and 11 lows, even though contour detail should not redefine pressure systems.
- In the 61-frame NAM 3 km sample, 48,623,654 of 78,036,019 finite cloud-ceiling cell-frame values were at or above 50,000 ft after processing. Raw UPP records showed the 20,000 m no-ceiling sentinel; interpolation had already smeared it into neighboring values.
- A live Lambert-grid point test at 40 N, 125 W changed 10 m wind from raw grid-relative U/V of -0.888/-10.392 m/s to earth-relative +2.214/-10.188 m/s, a direction difference of approximately 17.2 degrees.
- A live NAM 3 km F024 terrain check found 10,006 850-mb frontogenesis cells with absolute values above 100 C per 100 km per 3 h, including +3276.7 saturation, concentrated over high terrain where the pressure surface is underground.
- Pre-fix and corrected Cobb ratios differ materially: at -20 C the old calculation was about 20.927 while the pinned NBM-centered perturbation is about 16.466; at 0 C the old implementation returned missing while the corrected value is about 2.276.
- At otherwise unit-normalized inputs, the pre-fix effective SCP was 4.0 for MUCIN -100 J/kg; the SPC CIN term makes it 1.6. At -250 J/kg it is 0.64, a 6.25-fold reduction from the old result.
- On checked-in simple-synoptic and 500-mb-height fixtures, source consolidation reduced one common overlay stack from exactly 23 GeoJSON sources to 3 and the duplicated serialized geometry proxy from 168,736 to 63,039 bytes per update (62.640 percent). The final nine-repetition run measured a summed JSON-stringify median of 0.6382 ms before and 0.2384 ms after, a 0.3998 ms proxy reduction. This is not a MapLibre render-time claim.
- A real-browser stress check used the cached 61-frame NAM 3 km run with temperature, 500-mb height contours, isobars, thickness, and centers enabled. A 121-step requestAnimationFrame scrub measured 16.7 ms median, 33.4 ms p95, and 50.0 ms maximum step cadence with zero Long Tasks or runtime errors. No absent-model manifest request occurred during the gesture; one intended NAM 3 km latest-manifest refresh ran after the 250 ms trailing warmup. This is one headless-Chromium/simple-vector/machine result, not a universal device guarantee or an isolated GeoJSON-render delta.
- The optional science benchmark has now been rerun independently. Across the three audited local runs, modeled additive 21-level DCAPE cost was 3.647-3.802 CPU s/CONUS frame, modeled reduced-profile STP marginal cost was 11.771-11.909 CPU s/frame, and measured row-aware-center marginal cost was 2.846-2.980 ms on the synthetic 119×73 case. Full sorted samples are emitted so local timing variability is visible rather than hidden.

## Timeline latency root cause and target behavior

The reported lag is not primarily caused by isobar or height-vector size. It is a scheduling and cache-priority inversion:

1. Timeline warmup queues the binary hover file for every frame.
2. Hover files are tens of megabytes compressed and hundreds of megabytes decoded, while contour vectors are usually only kilobytes.
3. Height vectors are not included in the warmup set.
4. Warming is anchored to the first frame or first selected anchor, and the initial follow-up implementation aborted still-useful in-flight work whenever the selected hour changed.
5. Raster warmers can duplicate requests, and vector hooks briefly retain the prior frame's payload.
6. MapLibre receives repeated style mutations even when style identity has not changed.

The implemented correction prioritizes current and adjacent display artifacts and no longer warms an entire run's hover archive. Hover loads only for the active frame after a 750 ms retained-pointer debounce, while genuine pointer entry can request immediately. Decoded hover grids use a true LRU capped at six entries and 512 MiB; obsolete shared requests abort when their last consumer leaves. Synoptic and height vectors warm selected-first around the active frame. Moving within an unchanged URL/task roster preserves in-flight work and only reprioritizes the queued remainder; if all 12 ordinary panel slots are occupied, exactly one selected-hour request may temporarily raise concurrency to 13, and later selected assets advance as that urgent slot frees. A failed vector task receives one retry when its hour becomes selected. A selected raster already causes MapLibre to request the visible image, so its success restores shared status without a duplicate prefetch transfer. Changing the run, layer roster, detail mode, or request URLs aborts the genuinely obsolete plan. An identical same-anchor plan is a no-op, panel status writes are coalesced to one animation-frame commit, and global cache notifications are grouped into 100 ms bursts. Cross-model background discovery waits for 250 ms of timeline stability, deduplicates in-flight model/view probes, and backs off any failed/absent manifest probe for 60 seconds; failed background asset tasks become eligible again after 15 seconds even at the same anchor, and the periodic force refresh can still discover a newly built run. Image fetch/decode work is shared, parsed-vector eviction invalidates readiness, and cached current payloads are read synchronously. Vector state is keyed to the frame/request identity, the manifest H/L roster remains visible while a vector loads, and raster fallback remains visible only when it honestly represents the requested components. This addresses the reported isobar/thickness/center/height lag while reducing network and memory use.

Detailed synoptic mode no longer silently resolves to a simple vector. The UI reports `loading` or `fallback`; the combined isobar/thickness raster is suppressed when only one of those independently selectable components is requested, because showing it would violate the toggle. Simple and detailed vectors share one canonical H/L roster. The center-only analysis is approximately 50 km on CONUS (119 by 73 cells), hard-capped at 128 by 80, with 3.264–3.507 ms baseline median across audited runs (4.185 ms pinned p95), and adds no fetch or artifact bytes. Existing artifacts rebuild once because the renderer signature changed.

### GeoJSON source consolidation and measured proxy

The source consolidation is complete. Synoptic isobar/thickness lines and labels use 1 filtered family source instead of 16 sources; H/L centers use 1 instead of 2; and each active pressure-height parameter uses 1 instead of 5. Therefore a typical synoptic-plus-one-height stack is exactly 23 sources before versus 3 after. If all five height parameters are active simultaneously, the corresponding arithmetic is 43 versus 7. Feature filters preserve per-layer style classes and test/introspection counts. The registry updates one source once per `FeatureCollection` identity, survives removal of any non-final member, removes the source after the final member, and re-adds each family once after MapLibre style recreation.

`node scripts/benchmark-map-geojson.js` reproduces the checked-in-fixture measurement. It serializes every former collection and each consolidated collection over nine repetitions of 200 iterations. The exact geometry-volume proxy for the common stack is 168,736 to 63,039 bytes/update. In the final run, median stringify time was 0.468448 to 0.181425 ms for synoptic lines/labels, 0.001271 to 0.001189 ms for centers, and 0.168484 to 0.055782 ms for one height parameter: a summed 0.399808 ms/update reduction. These timings isolate duplicated JavaScript serialization only. MapLibre uses structured clone plus worker-side indexing, so actual per-frame browser render savings are device, map state, and worker-contention dependent and were not measured by this harness. The implementation adds no meteorological computation and no network bytes; it removes duplicate client geometry submission and source lifecycle work.

The following larger optimizations are not prerequisites for correctness:

- Removing compatibility fields, deduplicating labels, or increasing polyline quantization can reduce vector bytes, but changes payload compatibility or precision.
- Reducing contour smoothing/downsampling is not recommended merely for speed because the present values are defensible cartographic tradeoffs.

## Methodological transparency corrections

The analyst should be able to answer five questions from the interface or exported artifact: what field is this, at what valid time, from what run/model, how was it derived, and what approximation or display transformation was used.

Required wording principles:

- Say AGL or MSL wherever vertical datum can change interpretation.
- Say state, interval maximum, run maximum, or accumulation window rather than relying on a short parameter name.
- Identify model-simulated quantities such as hail and automated guidance centers.
- Distinguish raw hover values from smoothed or simplified presentation.
- Treat 540 dam as a synoptic thermal reference, not a deterministic precipitation-phase boundary.
- Call the hazard panel an app convective-environment heuristic, not a forecast, watch, warning, or SHARPpy-equivalent product.
- Identify proxy severe diagnostics and the 90-mb mixed-layer approximation explicitly.
- State learned-snow geography, SLR caps, preprocessing adaptations, and endpoint-versus-period-mean use.
- Make early accumulation windows dynamic: before a full 24 hours exists, say 0-to-N h or run-to-frame.
- Show actual fallback states when vectors are unavailable; do not silently change the perceived method.

## Defensible tradeoffs that are not defects

The audit deliberately does not flag the following as requiring scientific replacement when accurately described:

- GFS remains sampled every three hours by default, an explicit recurring-compute choice. Analysts can opt into the implemented 209-frame mixed cadence (hourly F000-F120, then 3-hourly F123-F384) when short-range trend resolution warrants the added work/storage.
- NAM's default configured-short tier remains F000-F036. The implemented full tier uses the official F039-F084 three-hour cadence: an unbounded Latest full-tier selection requires all 53 frames, a capped Latest request requires completion only through its cap, and an explicit still-uploading cycle caps to its contiguous published prefix. A complete full tier adds 16 frames, 43.243 percent more NAM frame work.
- Default gridded DCAPE uses a six-level reduced vertical profile. An opt-in CAM-only 21-level/current-numerics prototype is now available; full dense-grid sounding integration would still materially increase artifact-build compute.
- Effective bulk shear is a labeled proxy rather than an exact parcel-to-equilibrium-layer depth calculation.
- Native 90-mb MLCAPE/MLCIN remain the default gridded effective-STP input. An opt-in 100-mb source/reduced-profile prototype is now available, but dense 1 hPa parcel integration remains a high-cost point-analysis method.
- Veals V1c currently uses endpoint profiles. Constructing observation-period mean predictors needs additional temporal-profile handling and validation.
- Frontogenesis and some snow fields use presentation smoothing while retaining raw hover values.
- RF/Western skip learned inference and report 0 when positive liquid is at or below `0.1/60 in`; even the 60:1 cap cannot produce the 0.1 in minimum visible snowfall. This avoids profile/model work on display-inconsequential trace liquid. Other snow hover values remain unsmoothed.
- Simple and detailed contour intervals, contour smoothing, label collision control, and a finite center display cap are cartographic choices if clearly disclosed.
- Fractional interpolation of winter phase masks is a reproducible mixture treatment; nearest-category behavior is an alternative presentation philosophy, not automatically more truthful.
- An opt-in row-aware geographic-distance diagnostic now reports disagreements without changing the automated-center roster. Wind/closure validation and any decision to make the row-aware checks rejection gates still need regime validation.
- Exact schema-v2 temporal/tool provenance is implemented. Temporal/cache inputs are frame-local and source/record-resolvable; wgrib2 identity is deduplicated once per run manifest rather than repeated in every frame marker.

## Pipeline follow-up implementation and compute review

- **GFS mixed-cadence tier:** `--gfs-hourly-through-120` and the render-panel control produce 209 frames (F000-F120 hourly plus F123-F384 every 3 h) versus the unchanged 129-frame default. The audited cold fixture implies +80 frames, 17.05 worker-minutes, approximately 9.53 GiB of artifacts, and 3.86 GiB of selected-source cache per run. At the precision of those source measurements, that averages about 12.8 worker-s, 122.0 MiB of artifacts, and 49.4 MiB of selected cache per added frame. Idealized 18-worker compute-only time is about 56.8 seconds; real wall time is higher and workload-dependent because download, persistence, memory pressure, and the queue tail do not scale perfectly.
- **Exact provenance:** the bundled wgrib2 3.8.0 executable resolved and versioned/hashed in 23.469 ms once. Version capture combines trimmed stdout and stderr, with an stderr-only executable regression, so a valid tool cannot fail identity solely because of its output stream. A synthetic 146-record current frame measured 0.124 ms to construct and 0.036 ms to stringify a 47,827-byte schema-v2 sidecar. Adding 80 temporal sources measured 0.473 ms + 0.146 ms and 173,067 bytes. The completion marker stores one copy. Snowfall SLR predictors enumerate their surface/pressure-level records; each FRAM output explicitly links its liquid and environmental-profile terms; selected temporal outputs, required input roles, source times, raw inventory, hashes, byte ranges, reference-time-token agreement, and parsed statistical-window agreement all fail closed. Disk, shared-promise, and run-local memory hits restore the producing source refs rather than inheriting another frame's lineage.
- **Cadence/tool-safe completion and cache identity:** renderer v47 uses the stable model/tier identity for an exact canonical prefix and the exact run-level `wgrib2-sha256:…` tool reference, so extending a still-uploading or `--max-hour` prefix reuses its common completion markers while replacing wgrib2 invalidates them before the provenance catalog changes. A regular custom cadence gets a stable step identity; an irregular selection gets its exact roster SHA-256. Cumulative cache payloads are stricter: they hash the exact available source-hour roster bounded at or before the payload target, so GFS three-hourly and hourly tiers or a holed `0,6,12` selection cannot cross-reuse, while later future-hour publication does not churn an earlier target. The measured cost was 0.0116 ms for the first SHA-256 identity of a distinct target and 0.0000117 ms for a memoized lookup on the audit host.
- **Warm-cache lineage parity:** precipitation (`precip-accum-grid-v5-forecast-hour-roster`), run maxima (`run-max-grid-v6-target-bounded-provenance`), snow liquid/freezing-rain inputs (`snow-liquid-grid-v7-forecast-hour-roster`), snowfall deltas (`snowfall-delta-grid-v6-target-bounded-provenance`), cumulative snowfall (`snowfall-cumulative-grid-v6-target-bounded-provenance`), and profile predictors (`derived-profile-grid-v2-frame-local-provenance`) bind their sidecars to the applicable exact sources/target-bounded roster. Cold F006→F003 plus new-session warm-F003 regressions inspect the actual run-max, snowfall-delta, and snowfall-cumulative sidecars and prove that an outer future target cannot contaminate the earlier prefix.
- **Published-prefix behavior:** explicit date/cycle full-horizon requests probe their selected run and cap to the contiguous published prefix. The render control calls an all-concrete selection **Published prefix**, an all-latest unbounded official-horizon selection **Full horizon**, and a combined selection **Mixed: prefix + full**; the explanation states that a still-uploading concrete run may stop before its official horizon. The realized manifest remains authoritative. An unbounded latest official-horizon request requires a completed run, while capped/default latest selection may use a contiguous published prefix. This prevents deterministic failures on a deliberately selected still-uploading run without weakening the completed-run default.
- **Exact action progress:** the action server parses the builder's exact pre-frame per-model hour plan and resolved run lines. An unbounded latest build therefore reports 1/N rather than false 1/1 progress; a concrete uploading run replaces its provisional requested roster with the realized prefix; and final multi-model counts sum every matching result. This is constant-size job bookkeeping, not meteorological frame compute.

## Independent blind-spot review

The independent review was performed after the first complete finding register and again after implementation. Its job was to disprove or qualify proposed findings, identify omitted execution paths, and ensure a low-compute correction did not move a problem elsewhere.

The independent review found four important omissions from the first pass:

1. Point soundings bypass the map regrid path and sample raw Lambert-grid wind components. Because the map path correctly requests earth-relative winds, map wind verification alone did not validate sounding-derived hodographs, shear, storm motions, SRH, SCP, or STP. This is now SCI-02 and a mandatory correction.
2. Ceiling and UH sentinel/datum handling must cover the independent point-sounding path, not only raster generation.
3. Pressure-level fields and their derivatives need a terrain-validity mask. The observed extreme 850-mb frontogenesis saturation was not a quantization-range problem; widening the encoding would merely preserve false underground derivatives.
4. Run-union parameter manifests and transparent placeholder PNGs can make an unavailable layer look like a physically valid zero/dry field. Availability must be explicit per frame.

The reviewer also qualified two proposed fixes. Removing full-run hover prefetch is correct, but a completely cold selected-frame hover can move a tens-of-megabytes first-hover stall onto the analyst. The implementation therefore requests on real pointer entry, debounces a cursor retained across rapid frame changes, supports mirrored comparison hover, and byte-bounds the decoded cache rather than merely counting entries. For automated pressure centers, simply deleting all boundary/global candidates could lose real edge systems. The implementation scans near-edge candidates with a finite-data quorum and finite annular prominence while refusing literal boundary-only or global-extremum markers that cannot establish a closed system.

The post-implementation review then found and corrected additional blind spots:

1. A re-entrant single-URL hover request could overwrite its own shared-request bookkeeping and remain alive after all consumers aborted. The one-file path now uses exactly one shared request and has a two-consumer/last-abort regression test.
2. Official wgrib2 grid metadata may identify already earth-relative fields as `winds(N/S)`. That form is now recognized so the point-sounding rotation is neither skipped nor applied twice.
3. Retained hover previously bypassed the intended delay, a cache miss could leave the prior decoded payload resident, and a late value could be broadcast under the new frame identity. Pointer-entry and retained-pointer paths are separated; payload and values are request/frame gated.
4. H/L centers could disappear while a vector loaded, detailed mode could silently fall back to simple, and the combined raster could violate independent isobar/thickness toggles. 5. The declared 200 km center locality was being evaluated on simple-contour cells roughly as large as the locality itself. Center analysis now uses its own bounded approximately 50 km grid and one canonical roster for both contour detail modes.
6. Parsed-vector LRU eviction could leave global readiness and latest-run completion sets falsely marked loaded. Eviction now invalidates both sets, including the completion/eviction race, so a missing vector can rewarm.
7. A partially missing hazard-input set could fall through to `LOW`. The heuristic now uses tri-state threshold logic: missing data yields N/A whenever it could change the category, but irrelevant missing data does not suppress a category already established by known inputs.
