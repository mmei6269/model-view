# NOAA Beta Renderer Plan

This is the live plan for the NOAA beta renderer. Keep it focused on current behavior, useful constraints, and next work. Historical implementation notes belong in `docs/noaa-beta-implemented-products.md`; validation history belongs in `docs/noaa-beta-validation-log.md`; benchmark history, optimization history, and active optimization candidates belong in `docs/noaa-renderer-benchmark-history.md`.

## Scope

- Native NOAA beta renderer supports `gfs`, `nam`, `nam3km`, and `hrrr`.
- Source products are GFS `pgrb2.0p25`, NAM `awphys`, NAM 3 km `conusnest.hires`, and HRRR `wrfprs`.
- Current manifests are metadata-driven and must be regenerated after renderer/catalog signature changes.
- Accuracy is the first rule: omit unavailable derived products rather than showing dead controls or heuristic-filled fields.

## Current Behavior

- As of 2026-05-09, the NOAA renderer is the default local runtime and app data source.
- Local artifact generation uses `scripts/build-noaa-beta-artifacts.js` and writes to `output/noaa-beta-cache` unless `MODELVIEW_CACHE_ROOT` overrides it.
- The local dev server serves prebuilt NOAA artifacts through the React app; removed prior-renderer entrypoints should stay deleted unless a new NOAA-backed workflow explicitly needs an equivalent.
- Point soundings are available from the local artifact server for loaded NOAA model frames. The app opens them from a map double-click and samples the nearest GRIB grid point on demand.
- Point sounding UI follows an operational Skew-T workflow: large thermodynamic plot with wind barbs, height/isotherm markers, an explicitly labeled on-demand parcel trace, hodograph with Bunkers/mean-wind vectors, compact parcel/kinematic/lapse/critical-temp/composite tables, effective-layer diagnostics, and a possible-hazard signal that requires buoyancy.
- Skew-T wind barbs use the Northern Hemisphere convention: feathers/flags sit on the clockwise side of the staff (toward lower pressure). Fixed 2026-06-10 after the original implementation mirrored them.
- Point soundings target full scientific accuracy: compute is trivial at a point, so do not carry gridded compute-saving approximations into the point path when a reference-grade calculation is available.
- Direct products are implemented for planned upper-air, precip, cloud, radar, severe, winter, and CAM fields where source records exist.
- Derived scalar and derived accumulation products use the existing scalar PNG, legend, hover-grid, and manifest shapes.
- Implemented derived products include relative vorticity, surface LCL fallback, 700-500 mb lapse rate, surface theta-e, gust run max, UH run max, 0-6 km bulk shear, 0-3 km lapse rate, 700/850 mb frontogenesis, freezing-rain liquid, FRAM flat/radial ice, effective bulk shear, SCP, STP, and DCAPE.
- Palettes are treated as data. White/near-white stops that mean no ink are transparent, and intentional hard breaks are preserved.
- Frontogenesis uses the full Petterssen 2D kinematic form (deformation plus divergence terms; `petterssen-latlon-terrain-mask-v4` since 2026-07-11 — v3 `petterssen-latlon-finite-difference-v3` predated the terrain mask). The pre-2026-06-10 implementation omitted the divergence/convergence term. Hover values remain raw finite-difference values. Only the PNG presentation applies positive-only heavy smoothing.
- Relative vorticity uses a true zero-alpha ramp: exact zero is transparent, weak positive values fade into yellow, and weak negative values fade into gray without white/black halos.

## Severe Products

- Point soundings sample direct NOAA severe fields when they exist, but parcel-family CAPE/CIN and SRH diagnostics shown in the drawer are profile-derived for internal consistency. Direct fields such as PWAT, wet-bulb zero, PBL height, UH, hail, and model SRH remain useful source/context values.
- Point-sounding parcel work is on-demand only. Use it for sounding-specific diagnostics such as LFC/EL, Bunkers motion, storm-relative winds, effective-layer context, and composites that require a valid effective inflow layer.
- Point-sounding effective SCP/STP should remain missing when the effective inflow layer or required internally consistent parcel CAPE/CIN terms are not present; do not fill them with broad heuristics.
- Point-sounding parcel traces and parcel CAPE/CIN tables use the clicked-profile parcel calculation for internal consistency. Direct model CAPE/CIN fields remain sampled as source data but should not override point-sounding parcel-family diagnostics.
- Point-sounding surface LCL uses the clicked-profile parcel calculation from surface temperature/dew point first. The direct NOAA LCL height remains a fallback because direct zero samples can be misleading when the surface spread is nonzero.
- Point-sounding lapse-rate tables display virtual-temperature lapse rates for analyst use, with literal-temperature lapse rates retained as hover detail.
- Point-sounding SRH, EHI, and point-composite diagnostics prefer profile-derived SRH from the plotted Bunkers right-mover storm motion. Direct model SRH remains available as source detail and fallback.
- Point-sounding Bunkers motion uses the effective-inflow Bunkers method when effective layer and MU equilibrium level are valid, with fixed SFC-6 km Bunkers as fallback.
- Bunkers deviations (point and gridded, fixed and effective) are orthogonal to the SHARPpy `wind_shear` point-wind difference between the shear-layer bottom and top, fixed 2026-06-11. The pre-fix 500 m layer-mean shear endpoints understated right-mover speed (29 kt vs SHARPpy's 42 kt on the validation sounding) whenever a low-level jet sat inside the bottom mean layer, dragging SRH/EHI/STP low with it.
- Effective inflow layers (point and gridded) use the SHARPpy/SHARPlib top convention: the layer top is the last parcel-origin level meeting CAPE >= 100 / CIN >= -250, not the first failing level, and a layer that is still effective when the scan ends closes at the last passing level instead of being dropped. Point soundings scan every loaded profile row as a parcel origin; the gridded scan keeps the 25 mb minimum source spacing as a compute optimization.
- Effective bulk wind difference (point and gridded effective SCP/STP) spans the effective inflow base to 50% of the MU parcel equilibrium-level height with no minimum/maximum depth clamps, matching the SPC definition. The pre-2026-06-10 1-6 km depth clamps were removed.
- Point-sounding wet-bulb profiles (wet-bulb-zero fallback) use a pressure-aware Normand wet-bulb (Bolton LCL plus Wobus moist descent), not the surface-pressure Stull approximation. Gridded FRAM keeps Stull at the surface where it is valid.
- Point-sounding critical-temperature heights (0/-10/-20/-30C, wet-bulb-zero fallback) interpolate the crossing between bracketing levels. Fixed 2026-06-11: a `Math.max(1e-9, ...)` guard on the (normally negative) temperature difference collapsed the interpolation fraction to zero, snapping every critical height down to the level below the crossing (~300 m / ~1000 ft low against SHARPpy).
- Point-sounding 0-3 km CAPE is the SHARPpy-style mixed-layer parcel positive buoyancy below 3 km AGL (`b3km`), with the straddling segment clipped at 3 km; the direct model 0-3 km CAPE field remains a fallback (`modelCape0to3kmJkg`).
- Point-sounding SHIP follows SHARPpy `params.ship` (SPC 2014): MUCAPE, MU-parcel mixing ratio clipped 11-13.6 g/kg, virtual 700-500 mb lapse rate, 500 mb temperature capped at -5.5 C, sfc-6 km shear clipped 7-27 m/s, over 42,000,000, with low-CAPE/low-lapse/low-freezing-level reductions.
- Sounding and gridded effective-layer diagnostics use a fast pressure-segment mean wind through AGL layers, with height-mean fallback only when pressure interpolation is unavailable. This avoids dense pressure stepping in render loops.
- Sounding and gridded mixed-layer LCL diagnostics use a pressure-segment, mass-weighted lowest-100 hPa mean of potential temperature and mixing ratio. Direct MLCAPE/MLCIN remain preferred for CAPE/CIN values when present.
- Point-sounding Corfidi MCS vectors use the SHARPpy-style MBE method: 850-300 hPa non-pressure-weighted mean wind, or surface-300 hPa when the surface is already below 850 hPa, minus the surface-1.5 km non-pressure-weighted mean wind for upshear, with downshear as the deep mean plus that upshear vector.
- `SCP (0-3 km Proxy)` preserves the legacy/current SCP: MUCAPE, direct 0-3 km SRH, and the effective-inflow-gated 0-6 km shear proxy with the SPC shear cap at 20 m/s.
- `SCP (Effective Layer)` is separate: paired internally parcel-scanned MUCAPE/MUCIN, reduced-profile Bunkers ESRH, and reduced-profile EBWD with SPC-style normalization plus SPC MU-CIN damping. Effective-layer Bunkers motion is used when the effective layer and MU equilibrium level are valid, with fixed SFC-6 km Bunkers as fallback. Effective inflow parcel origins use every loaded profile row: 25 mb spacing from 1000-700 mb and 50 mb spacing from 700-300 mb.
- `STP (Fixed Layer)` preserves fixed-layer STP: surface-based CAPE, surface LCL, 0-1 km SRH, and 0-6 km bulk shear.
- `STP (Effective Layer)` is separate: MLCAPE, reduced-profile MLLCL, reduced-profile Bunkers ESRH/EBWD, and MLCIN, zeroed when the effective inflow base is above ground. EBWD uses the SPC-style 12.5 m/s zero gate and 20 m/s normalization capped at 1.5. Effective-layer Bunkers motion is used when the effective layer and MU equilibrium level are valid, with fixed SFC-6 km Bunkers as fallback. Effective inflow parcel origins use every loaded profile row, matching the SCP profile cadence.
- `DCAPE` (reworked 2026-06-11 for SHARPpy parity, `reduced-profile-dcape-v4` / `point-dcape-v4`): the downdraft source follows SHARPpy `params.dcape`: every above-ground level in the lowest 400 mb is scored by the mean theta-e of the 100 mb layer extending upward from it, and the parcel starts at the midpoint of the minimum-mean-theta-e layer (candidate pressure minus 50 mb) from the pressure-aware Normand wet-bulb of the interpolated temperature/dewpoint there, descending pseudoadiabatically to the surface. DCAPE is the net plain-temperature trapezoid buoyancy integral clamped to 0-4000 J/kg. Point soundings compute the layer means with 1 hPa steps and the exact Wobus pseudoadiabat; the gridded path uses knot-trapezoid layer means and the fixed-step moist-lapse Euler descent on the reduced diagnostic levels. The v3 variant (min point theta-e with a 100 mb mean parcel) understated DCAPE ~40% against SHARPpy on dry-slot soundings (675 vs 1120 J/kg on the validation sounding) and was replaced; v2 dry-adiabatic descent was worse and was replaced earlier.
- `camDcape21Level` and `effectiveStp100mbReduced` are explicit research artifacts, absent from default builds. They apply the current reduced numerics to the full 21-row CAM profile and a pressure-weighted 100-mb mixed-layer source respectively; neither is represented as dense point-method parity. `rowAwareCenterValidation` is also opt-in and diagnostic-only: it never changes the default H/L roster. Exact benchmark methods and costs live in `docs/meteorological-scientific-audit-2026-07-10.md`.
- Effective bulk shear is currently an effective-inflow-gated 0-6 km shear proxy. Cells must pass surface or mixed-layer CAPE/CIN thresholds, then the product reports fixed 0-6 km vector shear inside that mask.
- MUCAPE-only elevated instability remains masked until an elevated effective-layer base/top calculation exists.
- Gridded vs point CIN integration depth (documented-not-changed, 2026-07-02): the point pressure-step parcel path (`calculatePressureStepParcelCapeCinForSource`, `scripts/lib/noaa-beta/severe.js`) stops accumulating CIN above `PARCEL_CIN_TOP_PRESSURE_HPA` (500 mb), following the SHARPpy convention; the gridded segment path (`calculateSegmentParcelCapeCinForSource`, same file) integrates all sub-LFC negative buoyancy with no pressure cap, so gridded CIN (and CIN-gated products such as effective-inflow masks) can read modestly more negative than a point sounding at the same cell in deep or elevated regimes. Accepted as a gridded compute trade-off; aligning it would be an output-changing renderer edit subject to the exactness rule.

## Winter Methodology

- Reflectivity precip type is instantaneous `REFD + CRAIN/CSNOW/CFRZR/CICEP`, not an accumulation product. It can show snow or freezing rain where accumulated snowfall/freezing-rain liquid is zero or trace.
- Internal precip-type masks remain internal inputs for precip-rate/type, reflectivity/type, snowfall, freezing-rain, and FRAM products.
- `CICEP` is sleet/ice pellets. `CFRZR` is freezing-rain occurrence/type, not accumulation.
- Snowfall prefers direct accumulated snow-water sources (`WEASD`, HRRR `ASNOW`) when present. APCP-derived snow requires complete phase-mask records and rejects sampled phase-mask gaps.
- Kuchera and Cobb snowfall require complete profile inputs. If profile prerequisites are missing, omit the derived product or mark affected cells unknown rather than filling with a fallback.
- Accumulated snowfall preserves `NaN` as unknown through interval and cumulative merges. Verified finite zero intervals can carry totals forward; missing interval cells cannot silently undercount totals.
- Snowfall paint uses the source trace opacity ramp below `0.1 in`, while hover grids preserve trace values.
- Freezing-rain liquid uses direct accumulated `FRZR` when present; otherwise it uses accumulated APCP weighted by interval-average or sampled `CFRZR` fraction, with complete phase masks required.
- FRAM flat/radial ice is calculated only from freezing-rain liquid and sampled surface environment. Per-cell zero liquid returns zero ice without wet-bulb or wind work; trace liquid uses the supplied freezing-rain/ice opacity ramp.
- Winter sparse/dense equivalence (2026-07-17): the ≤45%-active sparse visitation is a pure compute optimization — FRAM null-vs-grid emission, failed-SLR-prediction cells, and FRAM fallback NaN-liquid cells produce identical results in both modes (sparse previously diverged: omitted FRAM layers, 0 instead of NaN). Non-finite liquid is always NaN (unknown), never 0.
- Learned-method trace skip (2026-07-17): RF/western-linear SLR inference skips cells whose per-cell ACCUMULATED liquid total is ≤0.1/60 in, so omitted snow stays mathematically below the 0.1 in display threshold at the 60:1 cap (the pre-fix per-chunk skip let trace chunks accumulate past it). Learned methodVersions bumped to `-domain-v3`, invalidating older snowfall caches.
- `snowHrrrAsnow` (and all snowfall/direct-derived kinds) honors `minForecastHour` (2026-07-17): HRRR F000 no longer selects or renders the trivially-zero 0-0-window ASNOW record. The `precipAccumulation` selection branch is deliberately not min-hour gated (realized per-frame availability already marks F000 precip unavailable; gating selection too is an open owner decision).

## Optimization Notes

- Detailed optimization history, benchmark fixtures, benchmark gates, rejected experiments, and active optimization candidates live in `docs/noaa-renderer-benchmark-history.md`.
- Keep `plan.md` limited to operational renderer behavior, durable decisions, and validation expectations; move future optimization logs/backlogs to the benchmark history doc.
- Derived-grid disk cache (2026-07-12): profile-derived severe products (lapse, bulk/effective shear, DCAPE, effective-layer SCP/STP, prototypes) persist next to the cached selected GRIB, keyed by the main decode's regrid-bin payload hashes, `derived-profile-grids-v1` (bump in `scripts/lib/noaa-beta/severe.js` when any pipeline formula/constant/gating changes), the active parcel backend, `CATALOG_VERSION`, and the requested product set. Hits restore exact Float32 bytes; `derivedGrids=` hit/miss appears in `--profile` logs; `npm run cache:clear` removes it with the cache root.
- Parcel kernel (2026-07-12, owner-approved relaxed tolerance; tolerance widened to all renderer surfaces later the same day — shifts must be reviewed/validated/benchmarked/documented per `docs/noaa-renderer-benchmark-history.md`): the effective-inflow origin scan and the reduced-profile DCAPE chain run in a WASM kernel by default. `MODELVIEW_PARCEL_KERNEL` selects `wasm-f32` (default: f32x4 SIMD scan + f32 DCAPE; documented sub-J/kg shifts and rare near-tie flips), `wasm` (scalar f64 NativeMath; measured artifact-byte-identical to JS on the PR #19 fixture — since kernel milestone 3 the scalar variant also routes the G1/G2 in-kernel product chains, whose NativeMath-vs-V8 ulp differences remained byte-absorbed on the 16-frame fixture but are bounded by test tolerance, not asserted as bit identity), or `js` (pure JS; reverts every numeric deviation). Point soundings and the pressure-step path remain pure JS at full precision. The derived-grid cache keys on the active variant, so grids from different backends never mix.
- Hover binary schema v3 (2026-07-12): the Int16 data region is a lossless global wrapping delta before gzip (-19% payload bytes); server and client prefix-sum it back. v1/v2 payloads remain decodable; merges re-encode at v3. There are no legacy clients (owner ruling).
- Intra-frame derived parallelism (2026-07-12, auto since 2026-07-14): `--derived-cell-concurrency` (env `MODELVIEW_NOAA_DERIVED_CELL_CONCURRENCY`) — sub-workers run the identical per-cell pipeline over disjoint slab-aligned chunks pulled from a shared queue (byte-identical by construction and by test; pools are prewarmed during fetch/decode, base/all payloads only). Default `auto` engages ONLY when the planned frame count is below the frame-worker pool width AND no explicit `--worker-count`/`--total-frame-concurrency` throttle was given; it then resolves `floor(cpuCount / plannedFrames)` clamped 1..16. Any build with at least a pool-width of frames — every full build, on every core count — and any explicitly throttled build resolves to 1 (off, exactly the pre-auto behavior; combine a throttle with an explicit `--derived-cell-concurrency=N` to get both). Explicit `N` forces a mode (`1`/`off`/`false`/`no`/empty disable; `true`/`on`/`yes` mean auto — same boolean vocabulary as input prefetch); an explicit value that oversubscribes a saturated pool (value x workers > cores) warns while staying honored; unrecognized values warn and stay off. Failure containment (2026-07-14 hardening): any parallel-path failure degrades to byte-identical serial compute via `computeParallelProfileDerived` (regression-tested with spawn fault injection — a committed vacuity mutation had silently removed this fallback), and prewarm can never throw into the frame worker's message handler. The server's render actions accept `derivedCellConcurrency` in the tuning object (1 = explicit off); the render panel does not expose it yet (its tuning inputs stop at worker/frame/range/decode concurrency).
- Input prefetch (2026-07-14, warm-first since 2026-07-15): `--input-prefetch=N` (env `MODELVIEW_NOAA_INPUT_PREFETCH`; default 8 pump slots x 3 range connections, clamp 0-16 slots, `0`/`off` disables, unrecognized warns and disables) — the frame queue warms each upcoming frame's main selected GRIB from the main process through the same `materializeSelectedGrib` locks/paths the workers use, so cold-build downloads overlap compute instead of alternating fetch waves with compute waves. The queue dispatches warm-first: part tasks and dependency chains keep their natural order, main frames the pump has warmed (or that are complete on disk) are preferred, and cold mains are deferred while preferred work exists — never starved (no preferred ready task -> first ready task, so a disabled pump is exactly the old FIFO; dependency gating is consulted for every candidate; retries stay FIFO). Dispatch mix appears in the `--profile` queue log as `dispatch=warm:X/cold:Y`. Cache-warming only: the worker fetch path is unchanged and authoritative, prefetch failures are swallowed and counted (`input prefetch: prefetched/skipped/failed` in the log), and outputs are byte-identical. Benefit scales with queue depth and inversely with network speed; single-wave builds are neutral. Hardening (2026-07-14, widened 2026-07-15): the pump's range width is capped at 3 connections per slot (24 total at the default 8 slots — not additive with the workers' `totalRangeFetchConcurrency` budget in steady state, since warm-first dispatch routes most fetching through the pump instead of the workers), lock contention makes it decline instantly (`onLockContention: "decline"` in `materializeSelectedGrib` — never the 10-minute poll loop or the unlocked last-resort fetch), and a module-load failure warns instead of silently disabling. Deferred follow-up: extract the shared fetch-prefix derivation used by the renderer and the prefetch module (lockstep-divergence guard) as its own fully parity-gated change.

- Compression pool (2026-07-16): `--compress-threads` (env `MODELVIEW_NOAA_COMPRESS_THREADS`; default 1, clamp 0-4, 0 = inline exactly as before) — PNG IDAT deflate and hover gzip run on per-render-worker helper threads through the identical codec entry points, overlapping raster/quantize work; bytes are identical by construction and 16-frame parity gated. Scanline building, hover pack, and the v3 delta stay on the render thread. Inputs are structured clones, so any pool failure (spawn error, worker death mid-job) falls back per call to the inline codec (`compressJobs=`/`compressFallbacks=` in `--profile` logs, `compressPoolJobs`/`compressPoolFallbacks` on the finalized profile object; `MODELVIEW_NOAA_TEST_COMPRESS_SPAWN_ERROR` is the test fault hook). Warm serial frame wall -20.7% at 1 thread, -25% at 2. Profile note: `corePng`/`catalogPng`/`hoverGrid` stages no longer include codec time; `compressWait` is the residual codec wait.

- Reflectivity gate fusion (2026-07-17): all gate variants for a reflectivity source render in one fused grid scan (compute the step bucket once per cell, write each gate buffer where `dbz >= gate`) instead of one full step-render pass per gate — up to 6 passes collapse to 2 with default gates `[10,15,20]` and both sources. Byte-identical (243/243 golden PNGs + unit fuzz); warm `corePng` stage sum -8.0% over the 16-frame pinned fixture.
- Synoptic climb field lazy build (2026-07-17): the H/L-refinement Gaussian field builds on first candidate instead of unconditionally; zero-candidate frames skip the full-display-grid blur entirely (micro: gfs ~97 ms -> ~0.006 ms per zero-candidate frame). Bit-identical field when candidates exist.
- Cache-wait probes (2026-07-17): `waitForCachedPrecipHourSources`, snow-liquid, cumulative-snowfall, and profile-grid waits poll the small JSON sidecars and read+validate grid bodies once after all refs land, instead of re-reading every cached body every ~120 ms poll. `waitForCachedGrid` accepts a `probe` option for remaining consumers.
- Renderer signature v48 (2026-07-17): completion identity now folds in the resolved `reflectivityGates` roster and a per-scale digest of byte-affecting fields (`min/max/alpha/minVisible/maxVisible/visibleRange/lookup/lookupSize/log/valueStops` + non-identity entry transforms). Catalog scale edits and gate changes now invalidate cached frames (previously stale bytes passed completeness); all frames re-render once on the first build after this lands.

- Synoptic per-candidate patch Gaussian (2026-07-17, backlog #43): the H/L-refinement climb field blurs padded per-candidate patches (`seed ± (travelPx + kernelRadius + 2)`) instead of the full display grid, with a full-grid fallback once cumulative patch area reaches 50%. Byte-identical (the refinement reads only the `travelPx` disc around each seed); `synoptic` stage -51.8% over the 16-frame fixture.
- Synoptic contour allocation slice (2026-07-17, backlog #22 partial): direct rasterization (Bresenham fused into `drawPolyline`), direct vector encoding from grid coords with chunked string assembly, and in-place chain merging — byte-identical (281-frame differential); `synoptic` stage a further -17% (cumulative -60% since the lazy build). Endpoint-indexed chaining was measured as a regression and reverted.
- Height-based profile interpolator fast path (2026-07-17, backlog #42): `interpolateProfileWindRows`/`interpolateProfilePressureRows` binary-search on a per-fill `heightBracketsValid` flag, exact against the linear fallback (720k-comparison fuzz); 1.27x on the calls, frame-level within noise in the July regime (the WASM kernel covers the effective path).

## Durable Decisions

- NOAA byte-range throttling accepts both callback limiters and `AsyncSemaphore`-style objects exposing `run(task)`. The point-sounding prefetch path passes the latter, so range reads must not bypass it.

- Derived severe and winter products must include formula/version/applicability metadata in manifests or sidecar metadata.
- Schema-v2 completion provenance must remain frame-local and exact: selected-subset SHA-256/ranges, raw and parsed time/statistic semantics, resolvable temporal terms, and one versioned/hashed run-level wgrib2 identity. The exact wgrib2 SHA-256 tool reference is part of renderer completion identity; temporal cache hits must restore the same bounded used-source lineage as cold calculation.
- Product availability stays manifest-gated by required inputs. If source records or profile prerequisites are absent, omit the product.
- Point sounding cache behavior must reuse selected/rendered GRIB cache records first; only add a lean point-sounding selected-GRIB cache when the rendered selection does not cover required sounding fields.
- Do not precompute expensive point-sounding parcel diagnostics during artifact builds. Cache missing raw/direct fields cheaply and run point-specific profile analysis only after the user requests a location.
- Do not use broad weather heuristics to skip meteorological calculations. Only skip when the value is definitively impossible, missing, zero, or intentionally unavailable by build mode.
- Do not downsample derived calculations and upscale them for operational layers.
- Do not hide trace calculations just because display thresholds would hide them, unless the output is mathematically bounded below that display threshold and the decision is documented.
- Use smoothed color interpolation where it improves continuous scalar readability, while preserving intentional hard transitions, category breaks, transparent ramps, and source-legend discontinuities.
- CAM-only or CAM-first products should be labeled that way in UI/config so GFS/NAM do not imply false precision.
- Snowfall RF remaining work: keep fixture-validating Node CONUS RF inference against sklearn when refreshing artifacts. The implemented western member is the fixed Veals V1c linear formula.

MapLibre migration decision log (2026-07-09, branch `maplibre-map-engine`):

- The map engine is MapLibre GL 5.24.0 over a locally served Protomaps vector basemap (`output/basemap/na.pmtiles`, HTTP Range route on the artifact server; `npm run basemap:fetch`). Leaflet, the raster-tile basemaps, and the dev engine flag are deleted (Task 6.3) — MapLibre is the only engine.
- Light is the default basemap theme (spec §8a.1): the weather color maps were designed for a white background. Dark remains an explicit Display-menu pick; stored explicit picks survive migrations, and the removed topographic theme migrates to light.
- Zoom is NATIVE MapLibre zoom app-wide (Task 6.2): persistence/permalinks carry a `zs=2` scale marker, legacy leaflet-scale values migrate by −1, and all in-code zoom thresholds are native-scale.
- Offline capable: after the one-time basemap fetch, boot and analysis run with zero non-localhost network (offline-boot spec pins it).
- Renderer center-extraction accuracy fix (Task 4.5, owner-blessed): synoptic H/L centers are refined at full grid resolution in the renderer; manifests carry the refined `synopticCenters`.
- Weather rasters draw through per-frame `ImageSource`s, synoptic isobars/fronts/centers and height contours are native GeoJSON line/symbol layers, and counties stay the one app-drawn detail feature (basemap county lines stop at z14 tile detail; the app layer keeps the meteorologist-tuned fade curve).
- Native overlay layers share one filtered GeoJSON source per source family: one for synoptic isobar/thickness lines and labels, one for centers, and one per active height-contour parameter. A source is updated once per collection identity and survives until its final member is removed.
- Timeline movement within an unchanged prefetch task roster reprioritizes pending work without aborting useful in-flight vector downloads. If the ordinary 12-request panel queue is saturated, exactly one selected-hour urgent request may temporarily raise it to 13; subsequent selected assets advance as that slot frees. A transiently failed vector task retries when its hour becomes selected. Raster selection already issues the visible MapLibre image request, so it recovers status from that load instead of duplicating the transfer with a simultaneous prefetch retry. Run/layer/detail/request changes replace the roster and abort obsolete work.
- An identical same-anchor prefetch plan is a no-op. Panel status updates are coalesced to one animation frame and global cache notifications to one 100 ms burst, preventing hot-cache render recursion without delaying meteorological frames.
- Cross-model latest-run discovery is a 250 ms trailing background task with per-model/view in-flight deduplication and a 60-second failed/absent-probe backoff; an explicit periodic force refresh still discovers newly published runs. Failed background asset tasks become eligible for a same-anchor retry after 15 seconds rather than remaining sticky.

UX-ops-suite session decisions (2026-07-07):

- Frame subsets are PREFIX-ONLY (`--max-hour`, wire `maxHour`): run-cumulative products (rolling APCP, run-max, accumulated snow/freezing rain) integrate over every prior rendered hour, so an f000..fN prefix stays byte-identical to the same hours of a full build while an arbitrary hour gap would not. The UI never offers gapped hour lists.
- Renderer tuning is per-request only (`tuning` wire object → builder flags in `buildBuilderArgv`), never process-global env mutation; server-side bounds mirror the builder's `clampInt` ranges so an accepted value is used verbatim.
- Job cancellation: queued jobs flip to `canceled` immediately and their chained successors still launch (a non-queued job's `launch()` flushes its own `_queue`); running jobs keep status `running` until the SIGTERM'd child exits (so `hasRunningJob` keeps blocking the model/run/view against a resubmit race), then settle as `canceled`, never `failed`.
- Cache mutations (`/actions/cache/prune`, `/actions/cache/clear`) refuse with 409 while any job is queued/running; prune is dry-run unless `dryRun:false`; clear requires the exact `confirm:"CLEAR"` token. Both reuse `planPrune`/`runPrune` retention rails (newest run per model never deleted).
- The URL is the full shareable app state: `p1..p4` panel roster (`model:layer,layer`), `c` viewport, `tl` timeline mode, `hour`, `view`; legacy `?model=&layer=` links still parse. Map viewport persists per view in `modelview.session.v2` (`viewports`); `modelview.session.v1` is a read-only legacy fallback whose zooms migrate by -1 on load.
- Panel ceiling is `MAX_PANELS = 4` (`next/src/config/panels.ts`), the single source of truth for grid layout, Add Map gating, URL roster, and persistence.
- Cross-panel hover uses a module-level bus (`next/src/core/hover-bus.ts`); Δ readouts subtract raw hover-grid samples of the same variable key, so they are unit-safe by construction.
- Sounding compare fetches the second model's latest BUILT run at the frame nearest the primary profile's valid time; export inlines computed SVG styles before rasterizing (Tailwind classes do not survive XMLSerializer alone).
- Parameter accuracy caveats live in `next/src/config/parameter-caveats.ts`, sourced only from documented limitations (plan.md, methodology audits) — never invent new caveats there without a doc trail.
- Panel overlays position from per-panel `--panel-inset-top/-bottom` vars (set from grid-row props in App): only top-row panels inset for the app header and only bottom-row panels for the timeline. Quarter panels (3-4 up) render compact chrome.
- Composite (overlap-mode) timeline statuses aggregate only panels that carry the valid time; a frameless or disjoint-run panel never forces "pending", and "unavailable" never blocks "loaded" (a permanent pending would stall hold-on-pending playback).
- Playback base interval is 600 ms at 1× (rebased 2026-07-07; 0.5× recovers the old 1200 ms pace). The sounding drawer sits at z-[1100], above the map's engine-owned controls.
- Legend accuracy contract (2026-07-07): the catalog emits `legendTickPositions` for EVERY gradient scale (value-accurate, display-scale aware); the runtime overlays current catalog metadata onto served manifests' existing parameter keys (`refreshManifestParameterMetadata` — keys are never added, preserving selective-build gating) and folds a catalog stamp into manifest ETags; `shared/modelview-config.json` layer legends are GENERATED via `scripts/generate-shared-layer-legends.js` and guarded by `tests-node/shared-legend-parity.test.js`. Units stay ASCII in data; display prettifying (°F, m²/s²) lives only in `formatUnitDisplay`.
